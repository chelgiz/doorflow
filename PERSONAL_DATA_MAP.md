# Карта персональных данных DoorFlow

**Назначение:** техническая инвентаризация для оценки обработки персональных
данных. Это не заключение о соответствии 152-ФЗ и не юридическая консультация.
Фактические цели, основания, сроки, операторы, получатели и география обработки
должны быть подтверждены конкретным магазином, поставщиком DoorFlow и юристом.

## Зафиксированная модель размещения и доступа

| Решение или требование | Статус | Зафиксированное положение / ограничение |
|---|---|---|
| Отдельная установка DoorFlow на каждый магазин: экземпляр приложения, PostgreSQL, учетные записи, секреты и backups; данные магазинов изолированы | PLANNED | Это принятое проектное решение для первых клиентов, а не утверждение о готовой, развёрнутой и проверенной инфраструктуре. Кодовая база поддерживает store-scoped логику, но реальная изоляция каждого развертывания должна быть проверена отдельно |
| Сервер и резервные копии в РФ | PLANNED | Принятое требование размещения. Фактический российский регион сервера, primary DB, реплик, логов и каждого backup не подтверждён |
| Централизованная подготовка обновлений и отдельная установка на клиента | PLANNED | Обновления должны выпускаться централизованно, но разворачиваться отдельно для каждой установки; безопасная процедура релиза/отката на клиентах не подтверждена как операционная практика |
| У технической поддержки DoorFlow нет постоянного доступа к данным магазина | PLANNED | Принцип поддержки. Не подтверждено кодом или аудитом инфраструктуры отсутствие технических путей доступа |
| Временный доступ поддержки по явному разрешению магазина, отдельной учетной записи, минимальным полномочиям и сроку, с журналированием и отзывом | PLANNED | Временная учетная запись, согласование, ограничение срока/полномочий, журнал входов и действий и отзыв после работ пока не реализованы/не подтверждены. Использование данных в собственных целях DoorFlow не допускается проектным принципом; условия договора требуют юридического закрепления |
| Магазин обычно является оператором; DoorFlow может обрабатывать данные по поручению | LEGAL REVIEW REQUIRED | Предварительная модель зависит от фактических целей и действий сторон, а также договора. | Поручение обработки | CLIENT RESPONSIBILITY | До передачи данных магазин и DoorFlow должны определить и оформить договор/поручение с условиями, предусмотренными ч. 3 ст. 6 152-ФЗ; состав условий и роли сторон требуют юридической проверки |

Статусы в этой карте:

- **IMPLEMENTED** — поле/контроль существует в коде/схеме.
- **VERIFIED LOCALLY** — проверено только в локальной среде.
- **PLANNED** — принято как проектное решение, но не подтверждено внедрением.
- **CLIENT RESPONSIBILITY** — действие конкретного магазина/оператора.
- **LEGAL REVIEW REQUIRED** — применимость или правовая квалификация требует юриста.

## Основание инвентаризации

Карта составлена по текущей Prisma-схеме `prisma/schema.prisma`, API в
`app/api/`, административной авторизации `lib/admin/auth.ts`, документации
`ARCHITECTURE.md`, `SECURITY.md` и резервному копированию PostgreSQL. Наличие
поля означает техническую возможность его обработки, но само по себе не
устанавливает цель или правовое основание обработки.

### Денежная информация

В `OrderPayment` есть сумма в копейках, заметка, получивший сотрудник и время.
В текущей модели нет номера банковской карты, CVV, банковского логина или токена
платёжного провайдера. Это не исключает, что сотрудник внесёт чувствительные
сведения в свободную заметку; запретить такие записи инструкцией и не подключать
платёжную интеграцию без отдельного проектирования.

### Утверждённая целевая карта движения (размещение пока PLANNED)

```text
Для каждого магазина — отдельный экземпляр приложения, БД, учетные записи,
секреты и backups (целевой сервер и backups в РФ; фактически не подтверждено):
Посетитель / сотрудник браузер
  ├─ публичная форма ─ HTTPS ─> Next.js API ─> валидация/расчёт ─> PostgreSQL магазина
  │                                                   └─ лимитер: хэш идентификатора
  ├─ admin session cookie ─ HTTPS ─> API с проверкой сессии и роли ─> PostgreSQL этого магазина
  └─ просмотр опубликованного каталога <─ Next.js ─< PostgreSQL / DEMO fixture

PostgreSQL ─> backup ─> age encryption ─> отдельное хранилище этого магазина в РФ
                                        (требование PLANNED, фактическая копия не подтверждена)

Сотрудник магазина <─ авторизованный admin UI/API ─> только разрешённые записи
Техническая поддержка DoorFlow: постоянный доступ не предполагается;
временный доступ только по согласованию, отдельной учетной записи, минимуму
полномочий/сроку, с журналом и отзывом (механизмы PLANNED, не реализованы).
Обновления централизованно подготавливаются, затем отдельно устанавливаются
для каждого магазина (процедура PLANNED, эксплуатационная проверка отсутствует).
```

Для текущего кода не обнаружены подключённые API телефонии, платежей, Telegram,
рекламы, аналитики или поставщиков. Их нельзя считать ни получателями, ни
отсутствующими во всём будущем развёртывании без проверки DNS, конфигурации,
скриптов сайта, Nginx и договоров. Внешняя доставка backup через `rsync`
технически предусмотрена, но целевая отдельная копия на магазин в РФ — принятое
требование PLANNED; конкретный хост/провайдер и фактическую географию проверить
не удалось.

### Потенциальная трансграничная передача

**Статус: LEGAL REVIEW REQUIRED.** Фактическое место обработки и список
получателей должны быть установлены для каждой установки до вывода о
трансграничной передаче.

Проектное требование — сервер, PostgreSQL и резервные копии в РФ (PLANNED).
Фактический регион приложения, primary DB, реплик, backups, журналов,
администраторского доступа и поддержки пока не подтверждён; договоры с
хостингом и подрядчиками не проверены. Поэтому фактическая трансграничная
передача не установлена. Магазин должен получить сведения от поставщиков, а
применимость ст. 12 152-ФЗ определить с юристом.
